# CPU regression sniff test

**Reviewed 15 November 2026:** Same-session source controls did not reproduce an aggregate CPU/FPS regression. Historical cross-date drift, presentation cost, private growth, limited widget coverage and the rare overlay stall remain distinct findings. Neither canvas variant is retained.

iRacing was activated before capture and checked periodically through the UI. These point observations and the absence of other automated UI inputs support the intended foreground protocol; continuous OS foreground state was not recorded.

14 November 2026. **An aggregate current-source CPU regression does not
reproduce in the short controls or the later full-window pair.** The full
pair measures 5.471% CPU for exact benchmark source versus 5.268% for current
main today. Both have poor overlay pacing, and current has a large renderer
stall. This is not an overall performance clearance or statistical equivalence.

The original short controls measure 6.576% old-source CPU versus 6.528% across
two current repeats. The code audit and full-window follow-up below preserve
their separate analysis windows and limitations.

The later [old-source Radar-off and paint-loop controls](./2026-11-14-cpu-sniff.md#radar-marginal-cost-and-paint-loop-controls)
show an existing Radar cost, a larger observed marginal cost on current main,
and no CPU saving from removing the recent paint cap. Source attribution
remains open; this report preserves the earlier five-pass series.

## Protocol and checks

Five accepted passes use the same frozen saved-profile seed and real replay
start: frame 129269, session 2, focus car 37, cockpit 9/1, 1x playback. Each
plays for 90 seconds; analysis is replay-play seconds 30–90. The controller
pauses at 92 seconds to keep shutdown outside the window. The existing
analyzer selects report buckets overlapping this window; one five-second
bucket may cross an edge. CPU means retain that analyzer convention rather
than clipping individual buckets. Logs start before
play; the evidence retains each offset used by the analyzer. The Radar-off
profile changes only its enabled flag. Each accepted pass retains three shared
display windows plus Gantry and all other enabled widget IDs.

iRacing is activated before the play gate and positively focus-checked during
each pass. No other app UI work or build/test runs occur during measurement.
Replay progression, session, speed and camera are checked in SDK samples.
Old runtime source is exported from a5200766 and all 1592 src files
verify against its Git blob hashes after CRLF normalization. Its launcher receives only the finalized
historical private-profile forwarding and replay-metadata corrections.
Current runtime source stays at 711552a1. Both Electron distributions were
already installed. Seed, executable, bundle, addon and raw-log fingerprints
are retained in the [evidence](./2026-11-14-cpu-sniff.json).

The first old-source attempt is excluded: its original launcher ignored the
private-profile argument, opened the regular profile and had a mismatched
19-widget workload. The corrected pass verifies the private-profile argument
in the actual Electron command line and reports the same 20 active widget IDs
as current full-profile passes. The regular configuration's migration rewrite
was recovered and restored only after matching the exact pre-test SHA-256
e23e6ffad33d1ab53713b81dc1cff15bfe3ed86a0e5cd7e9c6954b5b090885ff. The replay's original frame,
session, camera and 1x playback are restored; simulator graphics are unchanged.
No benchmark-owned Electron process remains.

## Radar marginal-cost and paint-loop controls

14 November 2026. **Radar already had a measurable cost in the old source,
but these short controls show a larger effect in current main.** This does
not establish a newly introduced Radar bug or complete a source bisect.

The later [GPU-process trace](./2026-11-14-radar-gpu-trace.md) localizes most
of the extra CPU to DXGI presentation. It narrows the next experiment to
transparent-window/compositor behavior while leaving source attribution open.

### Radar on/off

| a5200766 / Electron 45.2.0 |                 6.576 |                    5.752 |                     0.825 |      12.5 |
| 711552a1 / Electron 45.3.2 |                 6.528 |                    4.671 |                     1.857 |      28.4 |

Current Radar-on is the two-run mean; other cells are single accepted passes
from the same session. All play 90 seconds at 1x from frame 129269/session 2,
focus 37/cockpit 9/1. The existing analyzer selects five-second report buckets
overlapping replay-play seconds 30–90. Percentages are total machine CPU.
GPU-process CPU means CPU execution in Electron's GPU process, not GPU usage.

Old-source GPU-process CPU falls from 3.542% to
2.846% with Radar disabled. Current main's corresponding
values are 3.932% and 2.161%.
The same frozen seed is used, and both Radar-off seeds have the same hash;
only Radar's enabled flag is changed. Other active widget IDs match.

The result supports an existing cost, but does not support calling the entire
current effect unchanged. These are total-profile marginal costs, which can
include interactions with other widgets and the compositor. Current total
Radar-on CPU still resembles old-source total CPU, so savings elsewhere may
offset the larger observed Radar contribution. Repeated on/off pairs are
needed before treating the difference in contributions as stable.

### Paint-loop isolate

A temporary current-main experiment restores Radar painting on every rAF,
while retaining its timing counter. Everything else stays on current main,
including Input and track loading. The stock full-profile mean is
6.528% app CPU; the uncapped experiment uses
6.835%, with 4.177% in the GPU process.
Radar drawing is exercised at 33.108 draws/second
versus the stock repeats' 29.759 mean.
Removing the 60-paint cap therefore does not remove the measured cost. This
one-pass experiment gives no reason to revert that cap as a fix; it does
not prove the precise rendering/compositing cause.

Two archived-build attempts are excluded: the first records no Radar draws
in its analysis window; the second is aborted before measurement when the
preflight still fails that check. Their low or absent CPU results are not
used. The accepted experiment uses the established development build and
confirms Radar drawing before the foreground play gate.
